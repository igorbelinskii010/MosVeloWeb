# MosVeloWeb — велосеть ЦАО Москвы

**MosVeloWeb** — открытый инструмент, который оценивает каждую улицу Центрального
административного округа Москвы (ЦАО) по уровню стресса для велосипедиста и находит
«недостающие звенья»: короткие участки, где новая велодорожка сильнее всего улучшит
связность безопасной велосети.

Проект готовится для конференции «Инженеры будущего» 2027, секция «Инновации умного города».

## Зачем это нужно

В центре Москвы есть много спокойных улиц, переулков и парковых дорожек, где ехать на
велосипеде комфортно. Но эти спокойные куски часто не связаны между собой: между ними лежат
большие улицы с быстрым и плотным движением. Велосипедист не может спокойно доехать
из точки А в точку Б, даже если почти весь путь проходит по тихим улицам.

Инструмент отвечает на вопрос: **где построить велодорожку, чтобы на каждый метр новой
дорожки стало безопасно доступно больше всего мест, куда люди ездят** (метро, МЦД, вокзалы,
вузы, офисы, парки).

## Что получится (продукт)

Сайт с двумя картами:

1. **Карта оценок.** Каждая улица ЦАО окрашена по уровню стресса LTS 1–4.
   У каждого участка видна причина оценки: тип велоинфраструктуры, скорость, число полос.
2. **Карта приоритетов.** Разрывы в безопасной сети, ранжированные по пользе. При клике
   на разрыв открывается карточка: длина, польза и что именно он соединяет.

## Чем отличается от аналогов

| Аналог | Ограничение | MosVeloWeb |
|---|---|---|
| Bike Stress Map (Бостон), PeopleForBikes BNA | Только США, не учитывают российскую разметку OSM | Правила адаптированы под Москву и теги OSM в России |
| «Велофутуре» (КБ «Стрелка», 2021) | Разовое исследование с закрытым методом; называет улицы, но не считает эффект для всей сети | Открытый и воспроизводимый метод, обновляется вместе с OSM, ранжирует разрывы по приросту связности на метр |

## Метод

1. **Граф улиц ЦАО** из OpenStreetMap через OSMnx (с буфером 300 м вокруг округа,
   чтобы не терять связи на границе; цифры считаются только внутри ЦАО).
2. **Оценка стресса LTS** (Level of Traffic Stress) — адаптация методики
   Mekuria, Furth & Nixon (2012) под Москву по альбому велоинфраструктуры ДТ Москвы (2014)
   и велоруководству «Как адаптировать город для велосипедов и самокатов» (2022).
   - **LTS 1** — спокойно даже ребёнку;
   - **LTS 2** — комфортно большинству взрослых;
   - **LTS 3** — терпимо уверенным;
   - **LTS 4** — только для очень уверенных.

   Уровень зависит от типа велоинфраструктуры, разрешённой скорости, числа полос в одну
   сторону, типа улицы и ширины тротуара. Считаются **две оценки сети**:
   «по ПДД» (без тротуаров) и «с тротуарами» (широкий тротуар от 2,5 м = LTS 2, иначе 3).
   Все пороги и правила — в [`config/lts_rules.yaml`](config/lts_rules.yaml).
3. **Острова.** Убираем участки LTS 3–4 — спокойная сеть распадается на связные куски.
4. **Польза разрыва.** Сколько точек притяжения становятся безопасно достижимы
   в расчёте на метр новой дорожки. Жадный выбор даёт очередь строительства.
   Точная формула выбирается в блоке 2.
5. **Проверка.** Бэктест (OSM на начало 2025 против построенного за 2025),
   сравнение с ДТП с велосипедистами и СИМ, сравнение со списком «Велофутуре».

**Особенности ЦАО:** мало жителей и много поездок на работу и учёбу, поэтому пользу считаем
по точкам притяжения, а не по населению; много односторонних улиц (учитываем встречное
движение велосипедов `oneway:bicycle=no`); тротуары и велодорожки в OSM часто нарисованы
отдельными линиями рядом с проезжей частью.

**Известные ограничения:** перекрёстки пока не учитываются; у 65,6% улиц со смешанным
движением в OSM нет тега скорости, и подставляется значение по умолчанию (на карте такие
участки нарисованы пунктиром).

## Первые результаты (блок 1, данные OSM на 31.10.2026)

- Площадь ЦАО — 66,2 км²; в OSM внутри ЦАО 3 586 км улиц и дорожек.
- Сеть «по ПДД» (без тротуаров) — 2 318 км, тротуаров — 917 км.
- Отдельных велодорожек — 40,6 км, велополос — 30,5 км; защищённых велополос
  (с тегом `cycleway:*:separation`) — 0 км.
- Распределение по LTS ещё калибруется ручной проверкой улиц (шаг 5) и будет
  опубликовано после неё.

## Как запустить

Нужен Python 3.11 и обычный ноутбук. Команды для Windows:

```
python -m venv .venv
.venv\Scripts\activate        # каждый раз перед работой!
pip install -r requirements.txt
python src/01_download.py     # скачать улицы и точки притяжения из OSM (~5 мин)
python src/02_normalize.py    # привести теги OSM к единому виду
python src/03_lts.py          # присвоить каждому участку уровень LTS
python src/04_map_check.py    # карта outputs/maps/lts_check.html
```

| Скрипт | Что делает | Результат |
|---|---|---|
| `01_download.py` | Граница ЦАО, граф улиц и точки притяжения из OSM (Overpass) | `cao_boundary.gpkg`, `graph_raw.graphml`, `poi.gpkg` |
| `02_normalize.py` | Скорость, полосы, тип велоинфраструктуры, тротуары; убирает дубли и закрытые участки | `edges_norm.gpkg`, `edges_excluded.gpkg` |
| `03_lts.py` | Две оценки LTS («по ПДД» и «с тротуарами») с причиной | `edges_lts.gpkg`, `nodes.gpkg`, `outputs/lts_summary.txt` |
| `04_map_check.py` | Карта для проверки глазами: цвета по LTS, пунктир для значений по умолчанию | `outputs/maps/lts_check.html` |

Скрипты запускаются по порядку. Каждый читает результат предыдущего из `data/processed/`
и сохраняет свой туда же. Скачанное кэшируется в `data/raw/`, повторно не качается.
Бесплатные серверы Overpass бывают перегружены (ошибки 502/504) — скрипт ждёт и пробует
снова, прерывать его не нужно.

Файлы `data/processed/*.gpkg` в git не хранятся (они тяжёлые). Чтобы оба автора считали
по одним и тем же данным, готовые файлы выкладываются в
[Releases](https://github.com/igorbelinskii010/MosVeloWeb/releases) с версией
(например, `data-lts-v0.3`): скачать и положить в `data/processed/`.

## Структура репозитория

```
MosVeloWeb/
├── README.md
├── requirements.txt          версии библиотек
├── claude/                   контекст для ИИ-ассистентов: CLAUDE.md, задания блоков,
│                             журнал решений (decisions.md), заметки (notes.md)
├── config/
│   ├── download.yaml         сервер Overpass, теги OSM, точки притяжения
│   ├── lts_rules.yaml        правила оценки LTS и значения по умолчанию
│   └── map.yaml              оформление карты проверки
├── src/                      скрипты по шагам (01, 02, …)
├── data/
│   ├── raw/                  скачанное как есть (не в git)
│   └── processed/            результаты шагов .gpkg (не в git)
├── outputs/                  сводки и html-карты для проверки
└── web/                      сайт (блок 3)
```

Главный результат блока 1 для блока 2 — `data/processed/edges_lts.gpkg`. Нужные блоку 2
колонки: `u`, `v`, `key`, `name`, `highway`, `length_m`, `in_cao`, `lts` (сеть «по ПДД»),
`lts_sidewalk` (сеть «с тротуарами»), `lts_reason`. Их названия и смысл не меняем без
договорённости.

## Как работаем вдвоём

1. Перед работой: `git checkout main` и `git pull`.
2. Новая задача — новая ветка: `git checkout -b <короткое-название>`.
3. Готово — `git push` и pull request в `main`. Напрямую в `main` не пушим.
4. Pull request проверяет и сливает второй автор: читает код и задаёт вопросы.
5. Свои файлы правит их автор (см. «Авторы»); если нужно поменять чужой — сначала договориться.
6. Решения по методу — только вдвоём, одной строкой в журнал решений: дата — решение — причина — кто решил.

## Технологии

Python 3.11, `osmnx`, `networkx`, `geopandas`, `shapely`, `pandas`, `pyyaml`, `folium`.
Сайт (блок 3): статичный HTML + Leaflet, данные в GeoJSON, хостинг GitHub Pages.
Расчёты длин — в системе координат EPSG:32637 (UTM 37N), для карт — EPSG:4326.
Только бесплатные инструменты и открытые данные.
