# MosVeloWeb

Открытый инструмент, который оценивает улицы Центрального административного округа Москвы
по уровню стресса для велосипедиста (LTS 1–4) и находит «недостающие звенья» велосети:
короткие участки, где новая велодорожка сильнее всего улучшит связность спокойной сети.
Проект для конференции «Инженеры будущего» 2027, секция «Инновации умного города».

## Как запустить

Нужен Python 3.11. Команды для Windows:

```
python -m venv .venv
.venv\Scripts\activate        # каждый раз перед работой!
pip install -r requirements.txt
python src/01_download.py     # скачать улицы и точки притяжения из OSM (~5 мин)
python src/02_normalize.py    # привести теги к единому виду
python src/03_lts.py          # оценка LTS
python src/04_map_check.py    # карта outputs/maps/lts_check.html
```

Скрипты в `src/` запускаются по порядку. Каждый читает результат предыдущего из
`data/processed/` и сохраняет свой туда же. Все пороги и правила — в `config/`, не в коде.

Файлы `data/processed/*.gpkg` в git не хранятся (тяжёлые). Чтобы оба автора считали
по одним и тем же данным, готовые файлы выкладываются в
[Releases](https://github.com/igorbelinskii010/MosVeloWeb/releases) с версией
(например, `data-lts-v0.3`): скачать и положить в `data/processed/`.

## Структура

```
config/      настройки загрузки, правила LTS, оформление карты
src/         скрипты по шагам: 01_download, 02_normalize, 03_lts, 04_map_check, …
data/raw/        скачанное как есть (не в git)
data/processed/  результаты шагов (.gpkg, не в git)
outputs/     сводки и html-карты для проверки
```

Главный результат блока 1 для блока 2 — `data/processed/edges_lts.gpkg`. Нужные блоку 2
колонки: `u`, `v`, `key`, `name`, `highway`, `length_m`, `in_cao`, `lts` (сеть «по ПДД»),
`lts_sidewalk` (сеть «с тротуарами»), `lts_reason`. Их названия и смысл не меняем без
договорённости.

## Как работаем вдвоём

1. Перед работой: `git checkout main` и `git pull`.
2. Новая задача — новая ветка: `git checkout -b <короткое-название>`.
3. Готово — `git push` и pull request в `main`. Напрямую в `main` не пушим.
4. Pull request проверяет и сливает второй автор: читает код и задаёт вопросы.
5. Свои файлы правит их автор (см. «Авторы»); если нужно поменять чужой — сначала договориться.
6. Решения по методу — только вдвоём, одной строкой в журнал решений: дата — решение — причина — кто решил.
