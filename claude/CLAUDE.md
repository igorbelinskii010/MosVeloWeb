## 1. О проекте

**Что это:** открытый инструмент, который оценивает улицы Центрального административного
округа Москвы (ЦАО) по уровню стресса для велосипедиста и находит «недостающие звенья» —
короткие участки, где новая велодорожка сильнее всего улучшит связность безопасной велосети.

**Продукт:** сайт с двумя картами:
1. Карта оценок: каждая улица ЦАО окрашена по уровню стресса (LTS 1–4).
2. Интерактивная карта приоритетов: разрывы в безопасной сети, ранжированные по пользе;
   при клике на разрыв — карточка с длиной, пользой и тем, что он соединяет.

**Для чего:** школьная конференция «Инженеры будущего» 2027, секция
«Инновации умного города». Автор — ученик 10 класса, работает один, проект вайбкодится
с помощью ИИ.

**Чем лучше аналогов:**
- Bike Stress Map (Бостон), PeopleForBikes BNA — только США, не учитывают российскую разметку OSM.
- «Велофутуре» (КБ «Стрелка», 2021) — разовое исследование с закрытым методом, называет
  улицы, но не считает эффект для всей сети.
- Наш инструмент: открытый, воспроизводимый, обновляется вместе с OSM, ранжирует
  разрывы по приросту связности на метр новой дорожки.

## 4. Метод (кратко)

1. **Граф улиц** ЦАО из OpenStreetMap через OSMnx.
2. **Оценка стресса (LTS, Level of Traffic Stress)** — метод LTS v0.2 (согласован 31.10.2026),
   адаптация методики Mekuria, Furth & Nixon (2012) под Москву: уровень 1 (спокойно даже
   ребёнку) … 4 (только для уверенных). Зависит от типа велоинфраструктуры, скорости, числа
   полос, типа улицы, ширины тротуара. Две оценки сети: «по ПДД» (без тротуаров) и
   «с тротуарами». Правила — в `config/lts_rules.yaml` (в репозитории кода), описание
   с источниками — в `claude/LTS_v0.2_критерии.md`.
3. **Острова:** удаляем участки LTS 3–4, сеть распадается на связные компоненты.
4. **Польза разрыва:** сколько точек притяжения (метро, МЦД, вокзалы, вузы, офисы, парки)
   становятся безопасно достижимы, в расчёте на метр новой дорожки. Жадный выбор → очередь
   строительства.
5. **Проверка:** бэктест (OSM на начало 2025 vs построенное за 2025), сравнение с ДТП
   с велосипедистами/СИМ, сравнение со списком «Велофутуре».

**Особенности ЦАО, которые нужно учитывать всегда:**
- Мало жителей, много поездок на работу/учёбу → пользу считаем по точкам притяжения, а не по населению.
- Много односторонних улиц → учитывать `oneway` и встречное движение велосипедов (`oneway:bicycle=no`).
- Тротуары и велодорожки в OSM часто нарисованы отдельными линиями рядом с проезжей частью.

## 5. Данные (только открытые и бесплатные)

| Данные | Источник | Блок |
|---|---|---|
| Улицы, велодорожки, скорость, полосы | OpenStreetMap через OSMnx (Overpass) | 1 |
| Точки притяжения | OSM (`ox.features_from_place`), при необходимости data.mos.ru | 1–2 |
| История OSM на прошлые даты | ohsome API | 4 |
| ДТП с велосипедистами и СИМ | Карта ДТП (dtp-stat.ru, данные ГИБДД) | 4 |
| Список приоритетных улиц | «Велофутуре», КБ «Стрелка», 2021 | 4 |

Лицензия OSM — ODbL: на сайте и в работе обязательно указать «© участники OpenStreetMap».

## 6. Технологии

- Python 3.11+, `osmnx`, `networkx`, `geopandas`, `shapely`, `pandas`, `pyyaml`, `folium` (быстрые карты для проверки).
- Сайт (блок 3): статичный HTML + Leaflet, данные в GeoJSON, хостинг GitHub Pages.
- Система координат для расчётов длин и расстояний: **EPSG:32637** (UTM 37N). Для сайта — EPSG:4326.
- Версии библиотек фиксируются в `requirements.txt`.

## 8. Правила для ИИ-ассистента

**Объяснение — обязательно.** Автор должен сам защищать проект перед жюри
(критерии «Самостоятельность выполнения» и «Умение отвечать на вопросы»). Поэтому:
- После каждого нового скрипта или крупного изменения коротко объясни **по-русски, простыми
  словами**: что делает код, какие данные берёт, что получается на выходе, какие допущения
  сделаны.
- Комментарии в коде — на русском. Названия переменных и функций — на английском, понятные.
- Не используй сложные конструкции там, где хватает простых. Код должен читать десятиклассник.

**Работа по шагам.**
- Один шаг — один скрипт в `src/` с номером. Каждый скрипт читает файлы предыдущего шага
  из `data/processed/` и сохраняет свой результат туда же. Никаких скрытых состояний.
- Каждый шаг заканчивается проверкой глазами: карта в `outputs/maps/` или таблица со сводкой.
- Не делай несколько шагов за раз, если об этом не просили.

**Данные и честность.**
- Никогда не придумывай данные, числа, ссылки и названия улиц. Если чего-то нет — скажи.
- Если значение подставлено по умолчанию (нет тега в OSM), это должно быть видно
  в данных: отдельная колонка `*_source` со значением `tag` или `default`.
- Все пороги и правила — в `config/lts_rules.yaml`, не зашивать в код.

**Решения.**
- Не меняй метод (правила LTS, формулу пользы, территорию) без согласования.
  Предложи вариант и объясни плюсы и минусы.
- Каждое принятое решение записывай одной строкой в `claude/decisions.md`:
  дата, решение, причина.
- Интересные находки, цифры и проблемы для будущего текста работы — в `claude/notes.md`.

**Ограничения.**
- Только бесплатные инструменты и открытые данные. Никаких платных API и ключей.
- Код должен запускаться на обычном ноутбуке за минуты, не часы.
- Перед запуском долгой загрузки — кэшировать результат в `data/raw/`, чтобы не качать повторно.

## 9. Глоссарий

- **LTS** (Level of Traffic Stress) — уровень стресса для велосипедиста на участке улицы, 1–4.
- **Остров** — связная часть сети, по которой можно ехать только по участкам LTS 1–2.
- **Разрыв / недостающее звено** — участок с LTS 3–4, соединяющий два острова.
- **Точки притяжения** — места, куда люди едут: метро, МЦД, вокзалы, вузы, офисы, парки.
- **Бэктест** — проверка алгоритма на прошлых данных: предсказал ли он то, что потом построили.
- **СИМ** — средства индивидуальной мобильности (самокаты и т. п.).
